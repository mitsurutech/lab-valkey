# Docker Compose で動かす Valkey ラボ：Redis 互換のキーバリューストア、有効期限、リスト、ハッシュ、カウンターを学ぶ

[English](README.md) | [Français](README.fr.md) | [日本語](README.ja.md) | [Español](README.es.md)

[![check](https://github.com/mitsurutech/lab-valkey/actions/workflows/check.yml/badge.svg)](https://github.com/mitsurutech/lab-valkey/actions/workflows/check.yml)

授業でそのまま使える **Valkey ラボ**です。学校や学校法人が、生徒一人ひとりにデータベース、コンテナー、ブラウザー上のターミナルを用意できる [MitsuruTech ラーニングプラットフォーム](https://mitsurutech.co.uk/ja/learning)から提供しています。生徒はそれぞれ、専用の **Valkey**（Redis と同じコマンドを話すオープンソースのキーバリューストア）を使って、**SET と GET、有効期限のあるキー、リスト、ハッシュ、カウンター**を学びます。また、データをメモリに持つストアを止めて起動し直すと何が起きるかも確かめられます。生徒のマシンには何もインストールされず、入力した内容がほかの誰かに影響することもありません。

ファイルは `docker-compose` ファイル 1 つ、`compose.yaml` だけです。自分のマシンでもプラットフォームでも同じように動きます。プラットフォームでは、生徒ごとに専用のコピーが用意され、インターネットへの出口はありません。

## 中身

| サービス | イメージ | メモリ | 役割 |
| --- | --- | --- | --- |
| `valkey` | [`valkey/valkey:8.1.10-alpine`](https://hub.docker.com/r/valkey/valkey) | 64 MB | ポート 6379 のキーバリューストアです。名前付きボリュームに追記専用ファイルを持ちます |

約 3 秒で正常に起動し、待機中の使用量は約 4 MB です。権限のないユーザーで動き、保持できるのは最大 32 MB までで、それを超えると、サービスが強制終了されるのではなく書き込みが拒否されます。パスワードはありません。コピーの外からは何も届かないからです。

イメージはサードパーティのプログラムで、プロジェクト自身の公開イメージを変更せずにバージョンを固定して（`latest` は使いません）実行します。そのため、レッスンとレッスンの間でラボが変わることはありません。ここでは何もビルドせず、このリポジトリのものがイメージの中に配布されることもありません。

**Redis ではなく Valkey である理由。**Valkey は、Linux Foundation による Redis 7.2 の BSD-3-Clause ライセンスのフォークで、同じコマンドに応答します。そのため、ここで学んだことは Redis でも、Redis 互換のストアを提供するほとんどのサービスでも通用します。Redis 8 以降はライセンスが異なる（AGPL または RSAL）ため、このラボでは Valkey を使っています。

## ターミナルに valkey-cli はありません

プラットフォームのターミナルには `psql`、`mariadb`、`curl`、`git`、`nc` が入っていますが、Valkey のクライアントはありません。Valkey はコマンドをプレーンテキストの 1 行として受け付けるので、問題にはなりません。次の 1 行で、渡された単語をストアに送り、返事を表示する `v` という関数を作れます。

```bash
v() ( printf '%s\r\n' "$*" | nc -w 1 valkey 6379 )
```

続けて次のように入力します。

```text
$ v SET greeting hello
+OK
$ v GET greeting
$5
hello
$ v GET missing
$-1
```

返ってくるのは本物のプロトコル、**RESP** です。`+` は短い成功を表す語、`$5` は次の行が 5 バイトのテキストであること、`$-1` は「何もない」こと、`:3` は数値、`*3` は 3 つの項目が続くことを表します。`nc valkey 6379` を実行して、サーバーに直接 1 行ずつコマンドを入力することもできます。自分のマシンでは、代わりに `valkey-cli` や `redis-cli` を使えます。下を参照してください。

## 自分のマシンで動かす

Compose プラグイン付きの Docker が必要です。初回の起動では、イメージをダウンロードします。

```bash
docker compose -f compose.yaml -f local.yaml up
```

`local.yaml` はポート 6379 を `127.0.0.1` に限って公開するので、ラボには自分のコンピューターからしかアクセスできません。`valkey-cli -p 6379` や `redis-cli -p 6379`、または上のように `nc` で接続します。`Ctrl-C` で止め、`docker compose -f compose.yaml -f local.yaml down -v` で、データも含めて削除します。

## 進め方

1. **保存して取り出します。**`v SET greeting hello` を実行し、続けて `v GET greeting` を実行します。
2. **キーを期限切れにします。**`v SET code 1234 EX 5` で 5 秒間だけ保存されます。`v TTL code` はカウントダウンし、5 秒たつと `v GET code` は `$-1` を返します。
3. **リスト。**`v RPUSH tasks wake eat code` は `:3` を返し、`v LRANGE tasks 0 -1` で 3 つの要素を順に読み戻せます。
4. **ハッシュ。**`v HSET user:1 name Ada born 1815` は `:2` を返し、`v HGETALL user:1` はフィールド名と値を表示します。
5. **カウンター。**`v INCR visits` は `:1` を返し、もう一度実行すると `:2` を返します。足し算はストアが行うので、2 つのクライアントが同時に実行しても数え落としはありません。
6. **何が残るかを確かめます。**ラボを止めてから起動し直すと、`v GET greeting` は今も `hello` です。ストアはすべてをメモリに持つので速く、書き込みはすべて名前付きボリュームの追記専用ファイルに記録されるので、起動時にそこからメモリを作り直せます。`v CONFIG GET appendonly` は `yes` を返します。期限切れになったキーは戻ってきません。

## 教員の方へ

このラボには自動採点がありません。生徒が証拠を提出し、教員が、ほかのラボと同じように採点します。

**生徒自身の短いセッションでの返事を提出してもらってください。**有効期限付きのキーと、カウントダウンする `TTL`、リスト、ハッシュ、カウンターに加え、期限切れで何が起きたかを説明する 1 文と、ラボを止めて起動し直したあとに何が残っていたか、その理由を説明する 1 文です。最後の 1 文で、メモリとディスク上のファイルの違いを理解しているかが分かります。

**コースでの位置づけ。**データベースとデータストアの入門に向いています。キーバリューストアは、非リレーショナル型のなかで最も単純なものです。また、セッション、キャッシュ、カウンターといった、こうしたストアの使いどころを扱う Web 開発にも向いています。正確な表現は、ご自身の認定団体の単元でご確認ください。ここでは引用していません。

**誰が何を見られるか。**コピーは、起動した生徒だけのものです。そのモジュールを教えている教職員は、生徒の作業内容を確認するためにコピーを開けます。生徒の作業を開いたことはアクセスログに記録され、生徒はそれを読めます。

## ラボでできないこと

ラボにはインターネットへの出口がなく、ストアにパスワードはなく（ほかからは届かないため）、Web ページもありません。2 台目のサーバーへのレプリケーションなど、Valkey のほかの機能は複数のサービスが必要なので、このラボには含まれません。ストアには 64 MB が与えられ、データが 32 MB を超えると書き込みが拒否されます。

## トラブルシューティング

- **コマンドを実行しても何も表示されません。**先に、同じターミナルで `v` 関数を定義してください。ストアが起動していない場合は、ラボが実行中と表示されるまで待ってください。
- **返事が `$5` のように見えます。**それは次の行の長さで、エラーではありません。その次の行を読んでください。
- **自分のマシンで、ポート 6379 がすでに使われています。**`local.yaml` の左側の数字を変えてください（たとえば `127.0.0.1:6380:6379`）。

## ラボの検証

`test/check.sh` は、プラットフォームのランナーがすべてのサービスを起動するのと同じ条件（すべてのケーパビリティを削除、`no-new-privileges`、プロセス数の制限、メモリの制限、インターネットへの出口なし）でラボを起動し、そのネットワークの内側から、このページの内容を確認します。上のコマンドが示したとおりに応答すること、有効期限が切れること、停止前に書き込んだキーが起動後も残っていること、です。Docker が必要で、push のたびに実行されます。ページ上部のバッジがそれです。

```bash
test/check.sh
```
